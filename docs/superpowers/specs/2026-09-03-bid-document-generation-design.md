# 一键生成投标标书设计

## 目标与范围

在测算结果页提供“生成投标标书”按钮，把当前项目的122项真实测算结果写入现有 Word 母版，并下载可继续编辑的 `.docx`。本轮不修改测算规则、PPT流程、企业资料模块和模板内容。

## 用户流程

用户完成测算后点击“生成投标标书”。页面展示“校验测算数据、整理服务方案、套用标书模板、导出文件”四个阶段；成功后显示文件名并提供下载，失败时保留结果页并显示可理解的错误信息。

## 技术方案

- 前端复用现有PPT生成弹窗和轮询交互，向 `POST /api/bid/jobs` 提交当前页面保存的完整测算结果，再轮询 `GET /api/bid/jobs/:id`。
- 服务端复用 `scripts/bid-binding/bindings.mjs` 生成映射 JSON，再调用 `scripts/bid-binding/apply_bindings.py` 将数据写入 `output/bid-template/安序物业_住宅物业服务投标文件_双括号动态母版_清理版.docx`。
- 未启用的动作按测算结果判断并从对应服务表格中移除；启用动作写入适用范围、频次和配置人数。项目经理、服务期限等当前没有输入来源的字段使用模板约定的正式兜底文案，避免残留双括号占位符。
- 生成任务仅保存在服务器内存，输出到现有 `output` 目录；下载接口设置正确的 Word MIME 类型和中文文件名。第一版不做任务持久化、账号权限或历史记录。

## 数据校验与错误处理

服务端必须校验项目名称、年成本、四个分类和122项动作完整性，不能使用默认示例数据补齐。映射失败、模板缺失、Python运行失败或仍有占位符时，任务转为失败并返回简洁错误；临时测算文件与映射文件在任务结束后清理。

## 验收标准

1. 按钮提交的是当前项目测算结果，不是演示数据。
2. 生成的文件可由 Word 正常打开，项目名称和代表性服务动作与当前页面一致，未启用动作不出现在对应服务表格中，文档内没有 `{{...}}` 占位符。
3. 生成中、成功、失败三种页面状态可用，成功后可下载 `.docx`。
4. 前端交互测试、映射测试、服务端接口测试和一次真实模板生成均通过，并在 `/project/result` 实际页面核对按钮与弹窗。
