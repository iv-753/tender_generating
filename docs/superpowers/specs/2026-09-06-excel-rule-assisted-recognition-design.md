# Excel 规则辅助 AI 识别设计

## 目标

在不更换现有千问 API、不裁剪工作簿内容、不降低混乱 Excel 兼容性的前提下，用规则预先生成字段候选映射，减少 AI 从零检索和判断的工作量。目标是把当前约 55—65 秒的识别时间缩短到 20—40 秒；最终以实测为准，准确率不得低于现有结果。

## 核心边界

- 每次识别仍将完整的已提取工作簿文本发送给现有 AI。
- AI 仍是最终字段映射判断者，可以接受、修正规则候选或判定字段缺失。
- 规则只提供候选和证据，不直接覆盖 AI 判断，不因追求速度猜测数据。
- 不修改计算算法、项目参数结构、前端确认流程或 API 地址。

## 识别流程

1. 按现有方式读取所有工作表和非空单元格，保留工作表名、单元格地址和原值。
2. 规则引擎根据表头别名、单位、同一行/列邻接关系、历史与失效标记生成候选映射。每个候选包含字段名、来源地址、命中规则和可信度。
3. 将完整工作簿文本、候选映射和仍存在冲突的字段一并发送给现有 AI。提示 AI 优先核对候选，同时结合整份表格上下文纠错和补全。
4. AI继续返回现有统一映射结构；现有标准化逻辑负责读取原单元格、换算单位、推导城市档位并拒绝不存在的来源地址。
5. 前端继续展示统一的识别结果确认界面，不向用户暴露内部规则或模型切换。

## 第一版规则范围

- 覆盖现有项目基础字段、园林地库字段和楼栋字段。
- 支持常见表头别名、中文单位、百分比、万平方米以及“现状/历史/预算/失效”语义标记。
- 同一字段出现多个候选时只排序并标注冲突，不自行选定最终值。
- 规则无法判断的内容原样交由 AI 结合完整工作簿处理。

## 异常处理

- 规则引擎异常时自动退回当前“完整工作簿直接交给AI”的流程，不能阻断识别。
- AI返回无效地址或异常数值时继续由现有标准化逻辑拒绝并标记待补充。
- AI请求失败时维持现有错误提示，不返回未经AI核对的规则结果。

## 验收标准

- 两份现有测试 Excel 的最终项目数据与当前基准完全一致。
- 记录工作簿提取、规则候选、AI响应和标准化四段耗时。
- 两份表均继续完整传入 AI，API和模型保持不变。
- 至少一份代表性文件的总识别耗时低于当前实测均值 57 秒；目标区间为 20—40 秒，未达到时如实保留计时结果，不以降低准确率换速度。
- 规则异常回退、历史值排除、缺失字段和楼栋映射均有自动化测试。
