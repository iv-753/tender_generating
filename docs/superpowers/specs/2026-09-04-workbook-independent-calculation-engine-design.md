# 脱离 Excel 的物业测算引擎设计

## 1. 目标与边界

本轮只完成一个闭环：现有项目数据提交到 `/api/calculate` 后，由服务器内置的规则和代码直接生成 122 项服务动作、四类人员配置及年度成本，不再读取、下载或解析 `动态成本分析模型.xlsx`。

原 Excel 继续保存在内部工作区，作为迁移核对依据，不进入 Git、部署包、云端 Blob 或线上运行链路。本轮保持现有页面、接口请求、`CalculationResult` 返回结构、PPT/标书消费方式不变；不制作参数矩阵页面、不接数据库、不扩展其余服务动作，也不调整已知旧表业务口径。

## 2. 迁移原则

1. 第一阶段以现有线上结果完全一致为准。服务 17 项、清洁 48 项、绿化 51 项、客助 6 项，固定合计 122 项，“其他固定岗”继续排除。
2. 不把 Excel 公式字符串直接搬到线上，也不引入通用公式执行器。规则使用有类型、可校验的配置，计算使用明确的 JavaScript 函数。
3. 旧表中疑似引用错误、楼栋类型差异和明细成本与取整总成本差异，本轮按现状保留并锁入回归测试。业务确认后再单独纠正，避免迁移与改规则同时发生。
4. 规则结构为后续可编辑矩阵预留字段，但本轮不开放客户编辑。

## 3. 结构设计

### 3.1 规则数据

规则按职责拆分，避免形成一份难以审查的大文件：

- `action-catalog`：122 项动作的编号、分类、名称、属性、单位、数量来源和计算类型。
- `service-rules`：服务动作的发生概率、单位工时、附加工时、各等级频次和特殊计算参数。
- `cleaning-rules`：清洁动作的作业面、位置、数量来源、单位工时、各等级频次和可选项默认值。
- `greening-rules`：绿化动作的数量来源、单位工时、各等级频次和可选项默认值。
- `assistance-rules`：固定岗、面积配人、机动岗和领班的分级配人标准。
- `pricing-rules`：服务等级修正系数、城市成本档位系数及当前基准人工价格。

不适用字段内部保存为 `null`，后续矩阵页面显示为 `/`。数量来源使用受控枚举，例如 `occupiedHouseholds`、`pavedRoadArea`、`totalLobbyArea`，不允许执行任意代码字符串。

### 3.2 派生指标

独立模块先把项目输入转换为统一指标，包括门楼墙面、草坪与地被分区、乔灌木估算数量、各类楼栋的大堂/架空层/前厅/疏散梯/天台面积、车库总面积等。动作规则只引用这些指标，不直接重复计算项目几何关系。

### 3.3 三类计算器

- 事件工时计算器：用于客户服务。根据户数、发生概率、次数、单位工时计算年工时，再按现有年有效工时口径汇总并取整配人。
- 面积工时计算器：用于清洁和绿化。按适用数量、单位工时、年频次计算年工时，再按现有工日口径汇总、取整并计算成本。
- 岗位配人计算器：用于客助。按固定岗数量、面积配人标准、机动替换比例和领班比例逐项向上取整。

分类汇总继续采用现有“先汇总工作量、再向上取整人数、再计算实际年度成本”的口径；动作明细成本继续保留未取整工作量对应的成本，因此不强制要求动作成本之和等于分类实际成本。

## 4. 数据流与接口

数据流保持为：

`ProjectData → 参数校验 → 派生指标 → 122 项规则计算 → 分类取整与成本汇总 → CalculationResult`

`/api/calculate` 不再初始化 `formualizer`、加载私有 Blob 或读取本地 Excel，而是直接调用纯计算引擎。开发服务器和 Vercel 函数复用同一入口，避免两套算法。前端及文档生成模块无需改接口。

## 5. 异常处理

沿用当前项目字段校验，并增加规则启动校验：动作数量和分类数量必须正确；动作编号唯一；计算类型、数量来源和必要参数必须完整；分母不得为零；所有输出必须为有限非负数。规则本身无效时返回明确的系统配置错误，不用零值掩盖问题。

## 6. 验证与交付标准

迁移时使用本地 Excel 作为一次性对照计算器，生成覆盖四个服务等级、四个成本档位、不同楼栋类型数量、零面积/零户数和取整临界点的基准案例。纯计算引擎逐项比较动作名称、频次、数量、年频次、年工时、人数、动作成本、四类汇总和总成本；文本和整数精确一致，金额及工时使用明确的小数容差。

最终必须满足：

1. 默认示例及代表性变化场景均输出恰好 122 项，四类数量为 17/48/51/6。
2. 纯引擎与 Excel 基准案例在约定容差内一致，现有前端、PPT和标书测试通过。
3. 本机开发服务和 Vercel `/api/calculate` 均不访问 Excel，也不要求配置成本模型 Blob。
4. 生产依赖不包含 `formualizer`，部署配置、源码引用、网络请求和构建产物中不存在成本模型加载路径。
5. 实际页面从新建项目入口完成一次测算，结果页四类动作、人数、成本和单方成本显示正常。

## 7. 后续范围

本轮完成后再单独建设客户可编辑矩阵：以本设计的规则字段为列、122 项动作为行，项目级修改覆盖默认规则并支持恢复默认值。该功能需要独立设计交互、校验、保存和版本管理，不与本轮计算引擎迁移混做。
